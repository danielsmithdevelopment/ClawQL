# ClawQL Modularization & Intelligent MCP Orchestration

**Version 2.1** · June 2026

This document defines package boundaries, the dependency graph, Operator behavior, and the design of the intelligent MCP gateway. It serves as the authoritative reference for contributors and maintainers.

For the full platform vision, see the [Master Enablement Guide](./clawql-master-enablement-guide.md).

**Implementation status (June 2026):** [Modularization implementation status](https://github.com/danielsmithdevelopment/ClawQL/blob/main/docs/design/modularization-implementation-status.md) — what is extracted to `packages/` today vs this document’s target boundaries.

## 1. Vision & Core Objectives

ClawQL is a modular, production-grade, self-healing, multi-tenant AI memory and agent platform.

**Core Principles**

- Natural language is the primary interface for both humans and agents.
- `clawql-api` is the single intelligent MCP gateway. All interactions use `search()` and `execute()`.
- Optional packages and verticals have zero runtime footprint when disabled.
- Defense-in-depth (ATR, Presidio, Merkle rooting, policy enforcement) is applied uniformly at the gateway.
- All consumable artifacts originate from or verify against immutable ClawQL releases (Layer 0).

## 4. Dependency Graph

```
internals (merkle, cuckoo, utils)
         ↓
     clawql-core
         ↓
   clawql-api + clawql-pageindex
         ↓
(auth, documents, memory)
         ↓
(telemetry, sandbox, automation, goose, printingpress)
         ↓
     verticals
```

Strict acyclic graph, enforced by CI (ESLint + madge).

No vertical may import another vertical. Cross-vertical operations must route through `clawql-api.execute()`.

Layer 0 (clawql-release) depends only on core utilities and produces bundles consumed by all other layers via the gateway. For the full Layer 0 design (Radicle, Arweave, Rift, release manifest, adoption path), see [Hybrid Decentralized GitHub Alternative](/vision/immutable-releases).

## 5. Intelligent MCP Gateway (`clawql-api`)

`clawql-api` is the single surface for the entire platform.

**Capabilities**

- Native vertical plugins
- Proxy plugins for external MCP, OpenAPI, and GraphQL backends
- Automatic Memory 2.0 enrichment and release manifest verification
- Uniform ATR/Panguard enforcement and Presidio redaction
- Emission of Ouroboros position events on every `execute()`
- Circuit breakers, response projection, and full observability spans (OpenTelemetry + Langfuse)

All downstream calls (native or proxied) pass through the same security and auditing pipeline.

**Horizontal plugins:** memory, documents, and automation will register their MCP tools via `Plugin.onRegister` when composed — see [ClawQL plugin model](/reference/plugins).

---

## 6. Operator & Configuration

The Kubernetes Operator manages a ClawQLInstance CRD that controls:

- Tier (local / standard / enterprise)
- Vertical enablement
- Provider specs (Postgres, DuckDB, Vault, etc.)
- Resource limits and scaling
- Feature toggles (sandbox, telemetry, etc.)

When a vertical is disabled, its Effect Layer is not composed and contributes zero code or resources.

---

## 7. Cross-Cutting Concerns

**Security**: Classification gating, external model routing, WORM Merkle audit, and runtime enforcement (Tetragon/Falco) are applied at the gateway.

**Observability**: All layers emit structured events to the LGTMP stack. Langfuse handles LLM/tool chains. Full correlation is available in Grafana.

**Releases**: Every artifact consumed by the platform is verified against a ClawQL release manifest containing Merkle root, policy, and build provenance.
