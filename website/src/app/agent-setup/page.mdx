# Agent setup

Vault-first onboarding: one home for **memory**, **provider secrets**, and **MCP wiring** — better than pasting API keys into client config. {{ className: 'lead' }}

<Note>
  Run **`clawql init`** before connecting Cursor. Secrets live in
  **`~/.ClawQL/vault/providers.json`** (same shape as HashiCorp
  **`secret/clawql/providers`**). Memory tools use **`~/.ClawQL/Memory/`**.
  Default install loads the **opinionated stack** (Cloudflare, GitHub, Slack,
  Linear, Notion, Onyx). Use **`CLAWQL_PROVIDER=all-providers`** only for every
  bundled vendor plus Google top-50 and AWS top-50.
</Note>

## CLI (recommended)

**One command:**

```bash
npx -p clawql-mcp clawql onboard --interactive
```

Or step by step:

```bash
npx -p clawql-mcp clawql init --interactive
npx -p clawql-mcp clawql mcp-config --write cursor
npx -p clawql-mcp clawql doctor --smoke
```

Restart Cursor or Claude Desktop after MCP config is written.

## Copy-paste prompt

For agent-guided setup, copy the full prompt from the repo:
[agent-setup-prompt.md](https://github.com/danielsmithdevelopment/ClawQL/blob/main/docs/getting-started/agent-setup-prompt.md)

Highlights the agent should run:

1. **`clawql onboard --interactive`** — init, write MCP config, smoke test
2. Or **`clawql init --interactive`** → **`mcp-config --write cursor`** → **`doctor --smoke`**
3. **`clawql secrets set <provider>`** — add keys without editing JSON
4. Smoke **`search`** + read-only **`execute`** on one default-stack vendor
5. Optional **`clawql init --push-vault`** when HashiCorp Vault is available (K8s)

## Local vs cluster secrets

| Mode            | Secrets store                                            |
| --------------- | -------------------------------------------------------- |
| **Local stdio** | `~/.ClawQL/vault/providers.json` (loaded at MCP startup) |
| **Kubernetes**  | HashiCorp Vault → ESO → `clawql-provider-env`            |
| **Dashboard**   | Provider secrets UI → Vault KV                           |

Guide: [local-provider-vault.md](https://github.com/danielsmithdevelopment/ClawQL/blob/main/docs/getting-started/local-provider-vault.md)


## Cursor iOS (Cloud Agent)

The iOS app cannot run local stdio MCP or keep **`~/.ClawQL`** on the device. Use **Cursor Cloud Agents** instead:

1. **Dashboard Secrets** — `CLAWQL_HOME`, `CLAWQL_SYNC_*`, bucket credentials, and provider API tokens (never in git or **`mcp.json`**).
2. **stdio MCP** in **`.cursor/mcp.json`** — `npx -p clawql-mcp clawql-mcp`; enable the **clawql** server when starting an agent run from iOS.
3. **Team bucket** — shared **`Memory/`** via R2, S3, or GCS; end important runs with **`memory_sync`** `{ "direction": "auto" }`.

Full walkthrough: [cursor-ios-cloud-agent.md](https://github.com/danielsmithdevelopment/ClawQL/blob/main/docs/getting-started/cursor-ios-cloud-agent.md) (also on the docs site at [Cursor iOS + Cloud Agent](/getting-started/cursor-ios-cloud-agent)).
