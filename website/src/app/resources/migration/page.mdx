## Upgrading clawql-mcp

1. Check [GitHub Releases](https://github.com/danielsmithdevelopment/ClawQL/releases) for breaking changes
2. Update **`CLAWQL_*`** env vars if provider or feature-tier defaults changed — [Configuration reference](/spec-configuration)
3. For Kubernetes/Helm: bump image digest in values, run **`helm upgrade`**, verify **`/healthz`**
4. Re-run smoke tests: **`search`** on a known operation, **`execute`** dry path, vault **`memory_recall`** if enabled

## From other MCP servers

| From                   | To ClawQL                                                                                        |
| ---------------------- | ------------------------------------------------------------------------------------------------ |
| Raw OpenAPI in context | **`search`** + **`execute`** — specs stay on disk                                                |
| Single-vendor MCP      | Default stack or narrow preset — **`CLAWQL_BUNDLED_PROVIDERS=…`** · **`CLAWQL_PROVIDER=github`** |
| Full multi-vendor MCP  | **`CLAWQL_PROVIDER=all-providers`** (explicit opt-in)                                            |
| Custom tool servers    | Proxy via gateway or migrate to **`execute`** operations                                         |
| No vault memory        | Enable **`memory_ingest`** / **`memory_recall`** with Obsidian vault path                        |

## Default stack change (6.5.0)

Before **6.5.0**, an empty spec environment often implied **`all-providers`**. From **6.5.0** onward, bare **`npx clawql-mcp`** loads the **opinionated default stack** (Cloudflare, GitHub, Slack, Linear, Notion, Onyx). To restore the full merge:

```bash
CLAWQL_PROVIDER=all-providers npx -p clawql-mcp clawql-mcp
```

Helm **`clawql-mcp`** chart values may still default to **`all-providers`** for full IDP deployments — see [Kubernetes](/deployment/kubernetes).
