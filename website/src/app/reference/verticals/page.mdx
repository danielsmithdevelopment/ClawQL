# Verticals guide

Domain verticals (**lending**, **legal**, **healthcare**, etc.) are **plugins** — the same `Plugin.onRegister` model as memory, documents, and automation — scoped to an industry domain. They extend the gateway with domain-specific tools while sharing security, memory, and audit infrastructure. {{ className: 'lead' }}

<Note>
  **No vertical packages are shipped yet.** Browse every planned vertical
  alongside horizontal plugins in the [plugin registry](/plugins#registry)
  (filter by **Domain verticals**). Contribution rules live in the [Contributor
  Technical Specification](/contributing/technical-specification).
</Note>

## Verticals are plugins

| Concern             | Same as horizontal plugins? | Notes                                                                              |
| ------------------- | --------------------------- | ---------------------------------------------------------------------------------- |
| Registration        | Yes                         | `Plugin.onRegister` / Effect Layers when composed                                  |
| Opt-in footprint    | Yes                         | Disabled verticals have **zero runtime footprint**                                 |
| Cross-package calls | Via gateway                 | Verticals **never import other verticals** — use **`clawql-api.execute()`**        |
| Enable path         | Operator / CRD              | Planned **`ClawQLInstance`** flags (not shipped) instead of only `CLAWQL_ENABLE_*` |

See the full catalog on the [Plugins](/plugins) page — verticals are listed there as kind **Domain vertical**, not as a separate registry.

## Design rules

- Verticals **never import other verticals** — cross-domain operations route through **`clawql-api.execute()`**
- Disabled verticals have **zero runtime footprint** (Operator / `ClawQLInstance` CRD)
- Each vertical declares **`maxClassificationLevel`**, required ATR purposes, and Presidio policies

## Enabling a vertical

1. Set vertical flags in planned **`ClawQLInstance`** spec — see [Operator target architecture](/design/operator-target-architecture) §6 (not shipped)
2. Register vertical plugins at gateway startup per contributor spec § vertical packages
3. Run vertical-specific evaluation suites before production promotion
