How to read the trade

  • Direct HTTP — cheapest latency, zero gateway RSS, fat tokens. No MCP auth/audit/projection.
  • ClawQL — only arm that reduces tokens vs direct (~8,943 @12) while keeping task success. Pays ~16.1 ms flow p50 and Node RSS.
  • MCPJungle / agentgateway — fast multiplexers; they do not shrink payloads, so they cost schema tokens vs direct for little Layer2 benefit.
  • Executor — smallest Layer1 schema, largest Layer2 (full JSON pass-through); slowest flow p50 here.

3. Why move ClawQL from Node to Bun

Same dist/server.js and equal-arm env — only the JS runtime binary changes. Tokens are identical; Bun cuts the Node memory/latency tax without a Rust rewrite.

Bun is the low-pain lever, not the endgame. It keeps the Effect/TS governed path and buys ~¼ less Ready RSS and much better multiturn RSS/p50. It does not reach MCPJungle-class memory or beat Node on every chaos/p999 sample. A Rust rewrite would hurt more and might close more of the native gap later — Bun is the optional runtime track now.

What not to claim

  • Do not mix this topology-A stdio/HTTP board with NATS 4-replica concurrency ceilings.
  • Do not call a hand-written slim-return program “Executor” — live Executor is full pass-through.
  • Do not hide ClawQL RSS — admit the memory loss; Bun shrinks it, Go-thin proxies still win RAM.
  • Token wins require task_success — projection must keep the facts the agent needs.
