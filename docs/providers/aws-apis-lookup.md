# AWS APIs bundled lookup

ClawQL ships a **curated offline bundle** of 50 common AWS service OpenAPI specs, merged under the **`aws`** preset (same multi-spec model as **`google`** for GCP).

## Source of truth (live)

AWS publishes [Smithy API models](https://github.com/aws/api-models-aws) per service — not one merged OpenAPI. ClawQL uses community OpenAPI conversions from [APIs.guru](https://api.apis.guru/) ([aws2openapi](https://github.com/APIs-guru/aws2openapi)).

## Files in this repo

| File | Purpose |
|------|---------|
| [`providers/aws/aws-top50-apis.json`](../../providers/aws/aws-top50-apis.json) | Manifest: slug, service id, version, openapiUrl |
| [`providers/aws/aws-apis-lookup.json`](../../providers/aws/aws-apis-lookup.json) | Slim index generated by the fetch script |
| [`providers/aws/apis/<slug>/openapi.yaml`](../../providers/aws/apis/README.md) | Pinned OpenAPI per service |

## Using AWS with ClawQL

**Merged preset (recommended):**

```bash
export CLAWQL_PROVIDER=aws
export AWS_ACCESS_KEY_ID=…
export AWS_SECRET_ACCESS_KEY=…
export AWS_REGION=us-east-1
clawql-mcp
```

**Hybrid cloud (GCP + AWS + Cloudflare):**

```bash
export CLAWQL_BUNDLED_PROVIDERS=google,aws,cloudflare
```

**Default `all-providers`:** always includes every bundled vendor plus Google top-50 and AWS top-50 (only **`CLAWQL_ENABLE_DOCUMENTS=0`** trims the document/IDP stack). Fresh install with no spec env loads the **opinionated default stack**: Cloudflare, GitHub, Slack, Linear, Notion, Onyx.

## Authentication

AWS REST APIs require **SigV4** signing (not Bearer OAuth like GCP):

| Variable | Purpose |
|----------|---------|
| `AWS_ACCESS_KEY_ID` / `CLAWQL_AWS_ACCESS_KEY_ID` | Access key |
| `AWS_SECRET_ACCESS_KEY` / `CLAWQL_AWS_SECRET_ACCESS_KEY` | Secret key |
| `AWS_SESSION_TOKEN` / `CLAWQL_AWS_SESSION_TOKEN` | Optional STS session token |
| `AWS_REGION` / `CLAWQL_AWS_REGION` / `AWS_DEFAULT_REGION` | Region for `{region}` endpoints (default `us-east-1`) |

## Refresh

```bash
npm run refresh-aws-top50
```

Regenerates the manifest from APIs.guru (when catalog versions change) and re-downloads all pinned specs.

## Why not one giant AWS spec?

Same rationale as Google Cloud: hundreds of services, different hosts, colliding operation names, and impractical bundle size. The supported model is **one OpenAPI file per service**, merged at runtime with `specLabel` routing (e.g. `ec2-2016-11-15::GET_DescribeInstances`).

## Expanding beyond top 50

Edit `scripts/providers/generate-aws-top50-manifest.mjs` (priority list) or add entries directly to `aws-top50-apis.json`, then run `npm run refresh-aws-top50`.
