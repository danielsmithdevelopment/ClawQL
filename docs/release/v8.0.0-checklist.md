## Blocking gate — MCP Events ChatGPT live pass

**Do not tag `v8.0.0` until this passes.** Protocol/unit tests are not a substitute.

1. Complete every item in [`docs/specs/mcp/mcp-events-chatgpt-checklist.md`](../specs/mcp/mcp-events-chatgpt-checklist.md) against a ChatGPT plugin-connected ClawQL MCP server running the **exact signed RC image** that will be tagged `v8.0.0` (record **image digest** on the checklist). A pass on a dev build does not count.
2. **All seven** events must each get a real producer trigger and a real ChatGPT delivery (especially `stream.changed` watched-field + volatile-only negative, and `schedule.paused` auth pause → Reconnect sources).
3. For every delivery (and required negative), record **event ID** + matching **WORM** (`mcp_events.delivery`) evidence on the checklist — sign-off must be verifiable afterward (_verify us, don't trust us_).
4. Record operator sign-off (name, UTC date, commit SHA, **image digest**, PASS) in that checklist or the release PR comment.
5. Confirm `events/list` names match the public contract: `stream.changed`, `document.processed`, `hook.blocked`, `budget.exhausted`, `schedule.completed`, `schedule.paused`, `notification.sent`.
6. After tagging, confirm the published `v8.0.0` image digest equals the RC digest recorded on the checklist.

- Full separate registry publish of every `clawql-*` if OIDC still gated (audit wedge + observability have their own cadences).
