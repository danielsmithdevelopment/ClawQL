# ClawQL 8.0.0 purge inventory spec v0.1

**Status:** active trim plan (post PageIndex + CodeGraph purges)  
**Related:** [`docs/getting-started/migrate-to-8.0.md`](../getting-started/migrate-to-8.0.md), [`docs/reference/clawql-plugin-registry.md`](../reference/clawql-plugin-registry.md), [`docs/benchmarks/pageindex-ab-eval-spec-v0.1.md`](../benchmarks/pageindex-ab-eval-spec-v0.1.md)

## Goal

8.0.0 is a house-cleaning release. Do **not** bundle a tool unless it has a very clear purpose. Cleanup also improves Decide routing (tool/skill twins already caused a v0.5 classifier miss: `mcp.memory_ingest` vs `skill.clawql-memory-ingest`) and shrinks image scan / sign / defend surface.

### Target state

- **Default:** Core (`search` / `execute` / `cache` / `audit` / `skills_*`), memory (`memory_*` / `read_around`), and document ingest.
- **Everything else:** opt-in, each with a **named job**.
- **No twins by verb** (one agent-facing tool per verb; others become internal paths).
- **One converter** (Docling) and **one instrumentation layer** (OpenTelemetry).
- **Client-specific surfaces** (e.g. ChatGPT MCP Extensions) stay default-on and are gated by **capability detection**, not by flags that reverse the 8.0 decision.

This spec defines **how** to inventory and decide. The inventory table is seeded from the repo; **filtered call counts**, **enabled-deployment denominators**, and **image/CVE deltas** are filled before 8.0.0 ships.

## “Very clear purpose” test (all four required)

A tool (or ranker / hybrid switch) **stays bundled** only if it passes:

| #   | Criterion          | How to measure                                                                                                                                |
| --- | ------------------ | --------------------------------------------------------------------------------------------------------------------------------------------- |
| 1   | **Unique job**     | Does something no other bundled tool does (document the nearest overlap).                                                                     |
| 2   | **Evidence**       | Graded eval only — see [Evidence rules](#evidence-rules). Or a hard requirement (security, compliance, named integration) nothing else meets. |
| 3   | **Real usage**     | Filtered 60-day calls — see [Usage metrics](#usage-metrics). Applied mainly to **default-on** surface.                                        |
| 4   | **Worth carrying** | Dependencies + attack surface justified by 1–3. Track via [Payoff metrics](#payoff-metrics).                                                  |

**How to apply usage vs evidence**

- **Default-on tools:** usage bar matters (agents call what they see). High counts alone do **not** prove value — still need unique job + evidence.
- **Opt-in tools:** low/zero raw calls are expected while hidden. Judge primarily on **unique job + evidence**. Use `calls_per_enabled_deployment_day`; if `enabled_deployments = 0` for the window, that is its own signal (never turned on).
- **Client-specific surfaces:** omit from non-matching clients via capability detection. Do **not** flip them off with a product flag when they already add nothing to other agents’ tool lists.

**Defaults when data is missing**

- Zero filtered calls **and** no graded evidence → **purge** (or demote to optional out-of-tree plugin).
- Unproven default-off switches with no content-gain path on the current eval set → **remove now**; keep explicit knobs (`sources`, etc.); re-add only if an external bench (e.g. EnterpriseRAG-Bench) later proves them.
- Agent-facing specialist tools (PageIndex / CodeGraph rule): expose only if an **additive agent-loop** beat shows they help a working baseline. Server-side lifecycle can run without agent tools.
- Passes unique job + hard requirement but low usage → keep **opt-in** (`CLAWQL_ENABLE_*=1`), not default-on.

## Evidence rules

Only **graded evals** count as evidence:

1. There is an **off / control arm that could score** (not a ceilinged or contaminated fixture).
2. Report **n** (questions or tasks) and an **interval or exact sign-test p** (or equivalent).
3. Primary metric is **task completion / strict accuracy** (suite-defined). Latency/$ may be reported, never decisive unless the suite says so.

**Never count as evidence**

- Smoke runs, `contaminated-smoke`-tagged results, demos, manual “it worked once.”
- August OpenBench-style wins that used a flawed grader (applies to **every** tool, not only CodeGraph).
- Eval/CI traffic masquerading as production usage (see usage filters).

## Usage metrics

### `calls_60d` (filtered)

Count only **real sessions**, tagged by **client or tenant**.

**Exclude**

- pageindex-ab / OpenBench / CI / synthetic harness traffic
- Pre-GA operator self-use when tagged as such (or when `client`/`tenant` is missing and source is CI)

**Source of truth:** document which store (Loki audit vs inference call-store) and the filter SQL/query in the inventory fill PR.

### `enabled_deployments` + `calls_per_enabled_deployment_day`

For each opt-in tool/flag:

| Column                             | Meaning                                                                         |
| ---------------------------------- | ------------------------------------------------------------------------------- |
| `enabled_deployments`              | Distinct deployments (or tenants) that had the flag on for ≥1 day in the window |
| `enabled_deployment_days`          | Sum of days the flag was on                                                     |
| `calls_per_enabled_deployment_day` | `calls_60d_filtered / enabled_deployment_days` (null if denominator 0)          |

If **no deployment ever enabled** the flag in the window → record `enabled_deployments=0` and treat as a negative adoption signal, not as “zero calls = useless ranking.”

## Payoff metrics

Record **before and after** the purge cut for the default / recommended image:

| Metric                                                                  | Before | After | Δ   |
| ----------------------------------------------------------------------- | ------ | ----- | --- |
| Image size (compressed)                                                 |        |       |     |
| Production dependency count (`npm ls --omit=dev` or SBOM package count) |        |       |     |
| Open CVEs (OSV/Trivy critical+high+medium, same scanner rev)            |        |       |     |

Release claim form: “8.0.0 ships **N** fewer dependencies and **M** fewer open CVEs” (cite scanner + SBOM commit). Removing a converter stack (e.g. Tika) that pulls a JVM is an example of a high-payoff purge.

## Placeholder / vapor flags — purge in 8.0.0

Flags for features that do not exist yet, or that are already always-on via another path, must not ship as switches:

| Flag                                                             | Action                                                            |
| ---------------------------------------------------------------- | ----------------------------------------------------------------- |
| `CLAWQL_ENABLE_VISION` (reserved, no tools)                      | **Delete** from schema/docs                                       |
| `CLAWQL_ENABLE_OUROBOROS` (deprecated; harness always registers) | **Delete** from `.env.example` / docs; do not resurrect as a gate |
| Any other ENABLE with zero registration sites                    | **Delete** or implement before 8.0.0                              |

## Process

1. Regenerate inventory from code (not memory): flags + plugin tool names + skills.
2. Join filtered `calls_60d`, `enabled_deployments`, `calls_per_enabled_deployment_day`.
3. Attach graded evidence links (n + interval) or hard-requirement notes.
4. Record payoff baseline (image / deps / CVEs).
5. Decide: `keep` / `opt-in` / `prove` / `purge` / `consolidate` / `delete-flag`.
6. Land purge PRs with registration + flags + docs + migration notes together.

## Exit criteria for 8.0.0

- [ ] Inventory table filled: filtered calls + enabled-deployment columns.
- [ ] Every **purge** / **delete-flag** row has a PR; migration notes for default flips.
- [ ] Every **prove** row has a **graded** result (n+interval) **or** is removed from the agent-facing surface.
- [ ] No twin by **verb** without a documented primary path.
- [ ] One converter path (Docling) + optional unique-job `pdf-inspector`; no idle JVM converters.
- [ ] One instrumentation layer (OTEL); Langfuse/Prometheus as exports.
- [ ] `.env.example` matches live gates (no vapor flags; no removed hybrid master).
- [ ] Payoff table (image / deps / CVEs) recorded before vs after.

## Out of scope

- Provider OpenAPI packs (empty catalog is already 8.0 default).
- Customer private plugins.
